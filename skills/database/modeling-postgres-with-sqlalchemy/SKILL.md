# Modelado, indexación y transacciones en PostgreSQL

La base es la última línea de defensa de la integridad: constraints, tipos correctos y transacciones bien delimitadas. Los índices se diseñan a partir de las queries reales, no de las columnas.

## Contexto y reglas

**Modelado: hacer**

- `DeclarativeBase` con `MetaData(naming_convention=...)`: nombres deterministas de PK, FK, UQ, CK e índices, que Alembic necesita para alterarlos o borrarlos.
- Tipado 2.0 en todas las columnas: `Mapped[T]` + `mapped_column(...)`. La nulabilidad sale del tipo: `Mapped[str | None]` es nullable y `Mapped[str]` es `NOT NULL`.
- PK `BIGINT GENERATED BY DEFAULT AS IDENTITY` (`BigInteger` + `Identity()`). Usar UUIDv7 solo si los ids se generan fuera de la base o se exponen públicamente y no deben ser enumerables.
- Dinero en `Numeric(p, s)` + `Decimal`; timestamps con `UtcDateTime` (ver abajo) y `server_default=func.now()`. **`DateTime(timezone=True)` a secas no sirve si los tests corren en SQLite**: ahí pierde la zona, y `12:00-03:00` vuelve como `12:00` sin zona, que es otro instante.
- Estados y enums como `String` + `CheckConstraint("estado IN (...)")`, o `Enum(..., native_enum=False, create_constraint=True)` (VARCHAR + CHECK): agregar un valor no exige `ALTER TYPE`. Las dos formas son válidas; **una columna de valores cerrados sin CHECK no**: la base tiene que rechazar el valor inválido aunque escriba otro servicio.
- Reglas invariantes como `CheckConstraint` (`stock >= 0`): se cumplen aunque escriba otro servicio o un script.
- FK con `ondelete` explícito (`RESTRICT` por defecto para datos de negocio; `CASCADE` solo para hijos sin vida propia). PostgreSQL no indexa la columna FK solo: **crear el índice si el padre se puede borrar** (sin él, cada `DELETE` del padre recorre la tabla hija) **o si alguna query filtra o une por esa FK**. Si el padre nunca se borra (usuarios y catálogos que se desactivan) y nada consulta por esa FK, el índice solo encarece las escrituras.
- Relaciones con `lazy="raise"`: cualquier acceso no cargado explícitamente falla en desarrollo en vez de generar N+1 (o `MissingGreenlet` en async). El repositorio decide `selectinload` (colecciones) o `joinedload` (muchos-a-uno).
- `eager_defaults=True` en el mixin de timestamps: `created_at`/`updated_at` vuelven con `RETURNING` en el mismo INSERT/UPDATE.

**Indexación: hacer**

| Query | Índice |
|---|---|
| `WHERE customer_email = ? ORDER BY created_at DESC` | compuesto `(customer_email, created_at)`: primero igualdad, después rango/orden |
| `WHERE status = 'pending'` sobre pocas filas de una tabla grande | **parcial** `(created_at) WHERE status = 'pending'` |
| `WHERE lower(email) = ?` | de **expresión** `func.lower(email)` (o `CITEXT`) |
| `WHERE data @> '{"k": 1}'` (JSONB) | **GIN** `postgresql_using="gin"` |
| Lectura que solo necesita 2-3 columnas | **covering** `postgresql_include=[...]` (index-only scan) |
| FK de un padre que se borra, o usada en `WHERE`/`JOIN` | índice simple en la columna FK |

- Validar con `EXPLAIN (ANALYZE, BUFFERS)` sobre datos realistas antes y después.
- Columnas de baja cardinalidad (`is_active`, `status`) no van como índice simple: un parcial o un compuesto sirve más.
- Índices en tablas con tráfico se crean con `CONCURRENTLY` (ver `migrating-with-alembic`).

**Transacciones: hacer**

- **Unit of work = la sesión**: el service ejecuta el caso de uso y hace **un** `commit`. Ante cualquier excepción no se commitea nada.
- `async with session.begin_nested():` (SAVEPOINT) cuando una parte puede fallar sin abortar el todo (importaciones por lote, "crear si no existe").
- `SELECT ... FOR UPDATE` (`.with_for_update()`) para leer-modificar-escribir sobre una fila disputada (stock, saldo). `FOR UPDATE SKIP LOCKED` para colas de trabajos en tabla.
- **Serializar invariantes sobre rangos**: ver la sección de más abajo cuando la regla es "no se superpone con otra fila" y no hay una fila que bloquear.
- Bloqueo optimista (`version_id_col`) cuando la edición es larga (formularios) y los conflictos son raros: el UPDATE falla con `StaleDataError` y se traduce a 409.

**Evitar (anti-patrones)**

| Anti-patrón | Consecuencia | En su lugar |
|---|---|---|
| `Float` para importes | `0.1 + 0.2 != 0.3` en totales | `Numeric(12, 2)` |
| `DateTime` sin zona | ambigüedad en DST y entre regiones | `UtcDateTime` (rechaza fechas sin zona) |
| `DateTime(timezone=True)` y tests en SQLite | SQLite descarta la zona: el instante cambia en silencio | `UtcDateTime`: guarda en UTC y restaura la zona al leer |
| ENUM nativo para estados que evolucionan | `ALTER TYPE ... ADD VALUE` no corre en transacción y no se puede quitar un valor | `native_enum=False, create_constraint=True` |
| Validar unicidad solo en Python | dos requests concurrentes insertan duplicados | `unique=True` + capturar `IntegrityError` |
| `stock = stock - n` leyendo sin lock | sobreventa bajo concurrencia | `with_for_update()` o `UPDATE ... WHERE stock >= n` |
| Índice en cada columna "por las dudas" | escrituras más lentas, más WAL, más disco | índices por query medida |
| `lazy="select"` (default) en async | `MissingGreenlet` en runtime | `lazy="raise"` + carga explícita |
| `default={}` o `default=[]` | objeto mutable compartido entre filas | `default=dict` / `default=list` |

## Ejemplos

Base y mixins (`app/models/base.py`, verificado contra PostgreSQL 16 y SQLite):

```python
from datetime import datetime
from typing import Annotated, Any, ClassVar

from datetime import UTC, datetime
from typing import Annotated, Any, ClassVar

from sqlalchemy import BigInteger, DateTime, Dialect, Identity, Integer, MetaData, TypeDecorator, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_N_label)s",  # N: también nombra los índices compuestos
    "uq": "uq_%(table_name)s_%(column_0_N_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}


class UtcDateTime(TypeDecorator[datetime]):
    """TIMESTAMPTZ que solo acepta fechas con zona y siempre devuelve UTC.

    En PostgreSQL es `timestamp with time zone`. En SQLite la zona se pierde al guardar, así
    que se guarda en UTC y se la vuelve a poner al leer: los dos motores se comportan igual.
    """

    impl = DateTime(timezone=True)
    cache_ok = True

    def process_bind_param(self, value: datetime | None, dialect: Dialect) -> datetime | None:
        if value is None:
            return None
        if value.tzinfo is None:
            raise ValueError("naive datetime: use a timezone-aware datetime (UTC)")
        return value.astimezone(UTC)

    def process_result_value(self, value: datetime | None, dialect: Dialect) -> datetime | None:
        if value is None:
            return None
        return value.replace(tzinfo=UTC) if value.tzinfo is None else value.astimezone(UTC)


class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING_CONVENTION)


# BIGINT IDENTITY en Postgres; INTEGER en SQLite (necesario para autoincrement en tests).
BigIntPK = Annotated[
    int,
    mapped_column(BigInteger().with_variant(Integer, "sqlite"), Identity(), primary_key=True),
]


class TimestampMixin:
    # eager_defaults: trae created_at/updated_at con RETURNING en el mismo INSERT/UPDATE;
    # sin esto, leerlos después del commit dispara I/O implícito (MissingGreenlet en async).
    __mapper_args__: ClassVar[dict[str, Any]] = {"eager_defaults": True}

    created_at: Mapped[datetime] = mapped_column(UtcDateTime(), server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(
        UtcDateTime(), server_default=func.now(), onupdate=func.now()
    )
```

Entidades con constraints e índices por query:

```python
class Product(TimestampMixin, Base):
    __tablename__ = "products"
    __table_args__ = (
        CheckConstraint("stock >= 0", name="stock_non_negative"),
        CheckConstraint("price >= 0", name="price_non_negative"),
        Index("ix_products_name", "name"),
    )

    id: Mapped[BigIntPK]
    sku: Mapped[str] = mapped_column(String(64), unique=True)  # unique ya crea índice
    name: Mapped[str] = mapped_column(String(200))
    price: Mapped[Decimal] = mapped_column(Numeric(12, 2))     # dinero: nunca float
    stock: Mapped[int] = mapped_column(default=0, server_default="0")
    is_active: Mapped[bool] = mapped_column(default=True, server_default="true")


class OrderStatus(StrEnum):
    PENDING = "pending"
    PAID = "paid"
    CANCELLED = "cancelled"


class Order(TimestampMixin, Base):
    __tablename__ = "orders"
    __table_args__ = (
        CheckConstraint("quantity > 0", name="quantity_positive"),
        # Compuesto para la query real: "órdenes de un cliente, las más nuevas primero".
        Index("ix_orders_customer_email_created_at", "customer_email", "created_at"),
        # Parcial: solo las pendientes (pocas filas, consultadas por el job de cobro).
        # Parcial: en SQLite `postgresql_where` se ignora y un índice ÚNICO parcial se vuelve único
        # total. Para un índice único parcial, declarar también `sqlite_where` con la misma condición.
        Index("ix_orders_pending_created_at", "created_at",
              postgresql_where=text("status = 'pending'"), sqlite_where=text("status = 'pending'")),
    )

    id: Mapped[BigIntPK]
    customer_email: Mapped[str] = mapped_column(String(320))
    product_id: Mapped[int] = mapped_column(
        ForeignKey("products.id", ondelete="RESTRICT"), index=True  # se consulta por producto
    )
    quantity: Mapped[int]
    total: Mapped[Decimal] = mapped_column(Numeric(12, 2))
    status: Mapped[OrderStatus] = mapped_column(
        Enum(
            OrderStatus,
            name="order_status",
            native_enum=False,
            create_constraint=True,  # CHECK (status IN (...)): la base también valida
            length=20,
            values_callable=lambda e: [m.value for m in e],
        ),
        default=OrderStatus.PENDING,
        server_default=OrderStatus.PENDING.value,
    )

    # lazy="raise": prohíbe el lazy load implícito; cada query declara qué carga.
    product: Mapped[Product] = relationship(lazy="raise")
```

Carga explícita en el repositorio:

```python
async def get_with_product(self, order_id: int) -> Order | None:
    stmt = select(Order).where(Order.id == order_id).options(selectinload(Order.product))
    return (await self._session.scalars(stmt)).one_or_none()
```

SAVEPOINT por fila: una fila inválida no aborta el lote (verificado en SQLite y PostgreSQL):

```python
async def import_products(session: AsyncSession, rows: list[ProductCreate]) -> ImportReport:
    report = ImportReport()
    for row in rows:
        try:
            async with session.begin_nested():  # SAVEPOINT; sale con RELEASE o ROLLBACK TO
                session.add(Product(**row.model_dump()))
                await session.flush()           # fuerza el INSERT acá para atrapar el error de esta fila
        except IntegrityError as exc:
            report.skipped[row.sku] = type(exc.orig).__name__
        else:
            report.created.append(row.sku)
    await session.commit()
    return report
```

Cola de trabajos con `SKIP LOCKED` (N workers sin pisarse):

```python
async def claim_pending_orders(session: AsyncSession, batch: int = 50) -> Sequence[Order]:
    stmt = (
        select(Order)
        .where(Order.status == OrderStatus.PENDING)
        .order_by(Order.created_at)
        .limit(batch)
        .with_for_update(skip_locked=True)  # filas tomadas por otro worker se saltean
    )
    return (await session.scalars(stmt)).all()
```

## Serializar invariantes sobre rangos

"Dos turnos del mismo profesional no se superponen" no tiene una fila que bloquear: si la regla se valida con una query y después se inserta, dos requests concurrentes pasan el chequeo a la vez. La regla es **bloquear la fila padre que representa el recurso** (la agenda, el profesional) antes de chequear, y **releer** lo que el chequeo necesita después de tomar el bloqueo:

```python
async def lock_schedule(self, schedule_id: int) -> None:
    # Serializa a quien reserva sobre esta agenda hasta el commit.
    await self._session.scalars(
        select(Schedule.id).where(Schedule.id == schedule_id).with_for_update()
    )

# En el service, dentro del caso de uso:
await self._schedules.lock_schedule(schedule_id)
# Lo leído antes del bloqueo puede estar viejo: relee con populate_existing.
conflicts = await self._bookings.overlapping(schedule_id, start, end, refresh=True)
if conflicts:
    raise ConflictError("Time slot already taken")
```

`refresh=True` aplica `.execution_options(populate_existing=True)` a la query de superposición: sin él, la sesión devuelve la copia en memoria de una lectura anterior al bloqueo. Este invariante solo se prueba con concurrencia real contra PostgreSQL (receta en `testing-fastapi-endpoints`).

Bloqueo optimista:

```python
class Document(TimestampMixin, Base):
    __tablename__ = "documents"
    id: Mapped[BigIntPK]
    body: Mapped[str]
    version: Mapped[int] = mapped_column(default=1)
    __mapper_args__ = {"version_id_col": version, "eager_defaults": True}

# En el service: except StaleDataError → raise ConflictError("Document was modified by someone else")
```

## Checklist de verificación

- [ ] `Base.metadata` tiene `naming_convention`, y ningún constraint de las migraciones se llama `*_key`/`*_fkey` generado por Postgres.
- [ ] Toda FK cuyo padre se borra, o usada en `WHERE`/`JOIN`, tiene índice (`index=True` o compuesto que la encabeza). Las demás FK quedan sin índice a propósito.
- [ ] Importes en `Numeric`; timestamps con `UtcDateTime`; un test guarda `12:00-03:00` y lo lee como `15:00 UTC` con zona, en SQLite.
- [ ] Toda relación declara `lazy="raise"` (o una estrategia explícita justificada).
- [ ] Cada índice nuevo tiene la query que lo justifica y un `EXPLAIN (ANALYZE, BUFFERS)` antes/después.
- [ ] Hay test de concurrencia o de integridad para cada regla crítica (stock, saldo, unicidad).
- [ ] Todo campo de valores cerrados (estado, canal) tiene su `CHECK` en la base, sea `Enum` o `String`.
- [ ] Los services hacen un solo `commit` por caso de uso; los savepoints tienen un test que prueba el fallo parcial.
